# ФСП Оренбуржье — MVP: инструкция для чайников

Веб-приложение для региональной федерации спортивного программирования: соревнования, заявки, результаты, DOCX-протоколы, история спортсменов.

> Все персональные данные в проекте **фиктивные**. Это демонстрационная версия.

---

## Что вы получите

После запуска в браузере по адресу **http://localhost:8080** откроется сайт с четырьмя кабинетами: Федерация, Спортсмен, Тренер, Судья. Ничего устанавливать, кроме Docker, не нужно.

---

## Часть 1. Подготовка (делается один раз)

### Шаг 1. Установите Docker Desktop

1. Скачайте Docker Desktop: https://www.docker.com/products/docker-desktop/
2. Установите как обычную программу (Windows / macOS / Linux).
3. **Запустите** Docker Desktop и дождитесь, пока в нём появится надпись «Engine running» (зелёный индикатор).
4. Если на Windows просит включить WSL 2 — согласитесь и перезагрузите компьютер.

### Шаг 2. Проверьте, что Docker работает

Откройте терминал:

- **Windows:** PowerShell (Пуск → введите «PowerShell»)
- **macOS:** программа «Терминал»
- **Linux:** любой терминал

Введите:

```bash
docker --version
docker compose version
```

Если оба раза вы видите номера версий — всё хорошо. Если «command not found» — Docker не установлен или не запущен.

### Шаг 3. Перейдите в папку проекта

В терминале зайдите в папку, где лежит файл `docker-compose.yml`:

```bash
cd путь/к/папке/проекта
```

Пример для Windows: `cd C:\Users\Ivan\Documents\fsp`

Проверьте, что вы в нужном месте: команда `ls` (macOS/Linux) или `dir` (Windows) должна показать папки `backend`, `frontend` и файл `docker-compose.yml`.

## Часть 2. Первый запуск

### Шаг 4. Соберите и запустите проект

```bash
docker compose up --build -d
```

- Первый раз это займёт **несколько минут**: Docker скачивает образы и зависимости. Это нормально.
- Флаг `-d` означает «работать в фоне», терминал останется свободным.
- Backend сам применит миграции базы данных, а frontend подождёт, пока API будет готов.

### Шаг 5. Заполните базу демонстрационными данными

```bash
docker compose exec backend npm run db:seed
```

Эта команда создаст тестовых пользователей, соревнования, организации и справочники.

- Её можно запускать повторно — существующие данные она **не перезапишет**.
- Используйте её только для демо, **не** для рабочей базы.

### Шаг 6. Откройте сайт

В браузере откройте: **http://localhost:8080**

На экране входа есть кнопки быстрого входа для демо-аккаунтов.

## Часть 4. Пробный сценарий (что «покликать»)

Для двух пользователей одновременно используйте **два разных профиля браузера** (или обычное окно + окно инкогнито), иначе сессии перебьют друг друга.

### A. Создаём соревнование (Федерация)

1. Войдите как `admin@demo.fsp.local`.
2. Меню **Соревнования → Создать**.
3. Заполните: название, описание, дисциплина (выберите алгоритмическую), тип, возрастная группа **«открытая»**, даты, **дедлайн в будущем**, место, формат, уровень.
4. Сохраните как **черновик**.
5. Загрузите **положение** (файл PDF или DOCX, до 10 МБ).
6. Во вкладке **Судейская коллегия** назначьте судью (например, `judge`) и должность.
7. Откройте регистрацию (статус **OPEN**).

### B. Подаём заявку (Спортсмен)

1. В другом окне войдите как `multi@demo.fsp.local`.
2. Откройте созданное соревнование.
3. Нажмите «Подать заявку».

### C. Одобряем заявку (Федерация)

1. Вернитесь в окно администратора.
2. Соревнование → вкладка **Заявки** → **одобрить** участника.
3. Закройте приём заявок (статус **CLOSED**).
4. Перейдите в **Результаты**: укажите место и баллы, сохраните.
5. Нажмите **Опубликовать протокол**.

### D. Смотрим результат (Спортсмен, судья)

1. Спортсмен `multi`: **Мои результаты** → скачайте **DOCX-протокол**. Там же — уведомление.
2. Судья `judge`: **Мои назначения** — там появится это соревнование.

### E. Исправляем результаты (Федерация)

1. Измените баллы в завершённом соревновании → сохраните.
2. Скачайте протокол — это новая версия.
3. **Журнал действий** → запись `RESULTS` с данными «до» и «после».

### F. Связь тренера со спортсменом

1. Войдите как `coach@demo.fsp.local`.
2. **Мои спортсмены** → найдите `multi` по ФИО → запросите привязку по дисциплине.
3. Войдите как `multi` → **Мои тренеры** → подтвердите.
4. Снова под тренером: откройте любое открытое соревнование → **Регистрация** → подайте заявку за подтверждённого спортсмена.

## Часть 5. Повседневные команды

| Что нужно | Команда |
|---|---|
| Запустить (после первого раза) | `docker compose up -d` |
| Посмотреть логи backend | `docker compose logs -f backend` (выход — `Ctrl+C`) |
| Остановить (данные **сохранятся**) | `docker compose down` |
| Остановить и **удалить все данные** | `docker compose down -v` |
| Пересобрать после изменения кода | `docker compose up --build -d` |

> ⚠️ `docker compose down -v` удаляет базу и загруженные файлы **безвозвратно**. После него снова нужно выполнить шаг 5 (seed).

## Часть 6. Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop не запущен. Запустите и дождитесь «Engine running». |
| Сайт не открывается | Подождите 1–2 минуты после запуска. Проверьте `docker compose ps` — все сервисы должны быть `running`/`healthy`. Смотрите логи: `docker compose logs backend`. |
| «Порт 8080 уже занят» | Смените `WEB_PORT` в `.env` (см. ниже) и перезапустите. |
| Кнопка входа есть, но вход не работает | Проверьте, что вы выполнили шаг 5 (seed). |
| Ошибки после смены порта/домена | `APP_ORIGIN` должен **точно** совпадать с адресом в браузере, без `/` в конце. |
| Хочется начать с чистого листа | `docker compose down -v`, затем шаги 4–5 заново. |

## Часть 7. Необязательные настройки (`.env`)

1. Скопируйте файл `.env.example` в `.env`.
2. Что можно менять:
   - `WEB_PORT` — порт сайта (по умолчанию 8080);
   - `APP_ORIGIN` — адрес сайта в браузере, например `http://localhost:9090` (если меняете порт — меняйте **оба** параметра);
   - `COOKIE_SECURE=true` — включайте, если сайт работает по HTTPS;
   - пароль базы данных — только «URL-safe» символы (буквы и цифры, без `@ : / ? #`).
3. Примените: `docker compose up --build -d`.

## Часть 8. Для разработчиков: запуск без контейнеров приложения

Нужны **Node.js 22.12+** и **PostgreSQL 16**. По умолчанию порт базы наружу не открыт, поэтому используйте свой PostgreSQL либо временный Compose override с `127.0.0.1:5432:5432`.

**Терминал 1 (backend):**

```bash
cd backend
cp .env.example .env
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

В `.env` backend укажите `APP_ORIGIN=http://localhost:5173`.

**Терминал 2 (frontend):**

```bash
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173 (Vite сам проксирует `/api` на `localhost:3001`).

Проверка сборки: `npm run build` — отдельно в `backend` и в `frontend`.

## Словарик

- **Docker** — программа, запускающая приложение в изолированных «контейнерах», чтобы не ставить базу данных и Node.js вручную.
- **Docker Compose** — запуск сразу нескольких контейнеров (сайт, сервер, база) одной командой.
- **Seed** — наполнение базы тестовыми данными.
- **Миграции** — автоматическое создание таблиц в базе.
- **Backend / API** — серверная часть. **Frontend** — то, что вы видите в браузере.
- **Volume** — «хранилище» Docker, где лежат база и загруженные файлы; переживает обычный `down`.
