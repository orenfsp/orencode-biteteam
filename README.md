# Единая цифровая платформа Федерации спортивного программирования Оренбургской области

Полнофункциональный программный комплекс регионального отделения Федерации спортивного программирования (ФСП) Оренбургской области. Включает адаптивный веб-интерфейс, асинхронный REST API бэкенд, реляционную СУБД PostgreSQL, Telegram-бота для уведомлений и кодов верификации, почтовые рассылки (Email) и генерацию официальных документов с QR-верификацией.

```
Браузер ──► :8080  nginx (frontend-контейнер)
                    ├─ /            Статика веб-интерфейса (SPA)
                    ├─ /api/*  ───► backend:8000 (FastAPI + AsyncIO) ──► db:5432 (PostgreSQL)
                    ├─ /docs, /health (Swagger UI / OpenAPI документация)
                    └─ /verify/<№>  ──► Редирект на страницу проверки справки (QR-код из PDF)
```

Вся система работает в единой Docker Compose сети, наружу открыт **только один порт (8080)**. За счет единого origin отсутствуют проблемы с CORS.

## 🚀 Запуск через Docker за 3 шага

### Шаг 1. Подготовка конфигурации (`.env`)
В корневой папке проекта уже создан преднастроенный файл `.env` (также есть образец `.env.example`).
При необходимости отредактируйте параметры (порт, токен Telegram-бота, SMTP-почту):
```bash
cp .env.example .env
```

### Шаг 2. Сборка и запуск контейнеров
Запустите Docker Compose:
```bash
docker compose up -d --build
```
Команда соберет образы бэкенда и фронтенда, запустит PostgreSQL, накатит структуру таблиц, запустит планировщик задач и Telegram-бот.

### Шаг 3. Загрузка демонстрационных данных
После того как контейнеры перешли в статус `healthy`, выполните наполнение базы данных:
```bash
docker compose exec backend python seed_demo_data.py
```
*(Или через Makefile: `make seed`)*

## 🔧 Исправленные ошибки бэкенда

В ходе аудита и доработки кодовой базы бэкенда были устранены следующие ошибки:

1. **Отсутствие роутера судей в `router.py`**:
   * В `backend/app/api/v1/router.py` не был подключен `judges_router`. Эндпоинты `/api/v1/judges` и `/api/v1/judges/expiring` были недоступны (возвращали 404). Роутер подключен.
2. **`AttributeError: 'User' object has no attribute 'available_roles'`**:
   * В `backend/app/api/v1/users.py:70` вызывалось `current_user.available_roles`, отсутствовавшее в модели `User`. Добавлены вычисляемые свойства `available_roles`, `organization_name`, `active_role`.
3. **Ошибка сериализации `UserResponse` (`UserRead`)**:
   * В реестре пользователей `list_users` и `get_user_by_id` возвращались модели `User` с объектами `UserRole`, тогда как Pydantic-схема требовала `list[str]`. Добавлен нормализующий валидатор `@field_validator('roles', mode='before')` и предзагрузка связей через `selectinload`.
4. **Ошибка создания соревнований (`CompetitionCreate`)**:
   * В схеме `CompetitionCreate` отсутствовало поле `status`, при вызове `POST /api/v1/competitions` сервер падал с `AttributeError`. Поле `status: str = "draft"` добавлено.
5. **Пустые поля в связях тренер-спортсмен (`CoachAthleteRead`)**:
   * Модель `CoachAthlete` не возвращала `coach_name`, `athlete_name`, `discipline_name`. Добавлены соответствующие свойства в модель.
6. **Дублирование моделей рейтинга**:
   * В файле `backend/app/schemas/rating.py` устранены дублирующиеся объявления классов `RatingSettingRead` и `RatingSettingUpdate`.

## 🤖 Telegram-бот (Уведомления и коды верификации)

Файл реализации: `backend/bot/main.py`.  
Бот запускается **автоматически** внутри процесса бэкенда в Docker при указании `TELEGRAM_BOT_TOKEN` в `.env`.

### 1. Настройка токена:
1. Создайте бота в Telegram через [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. Откройте `.env` и впишите:
   ```env
   TELEGRAM_BOT_TOKEN=123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ
   TELEGRAM_BOT_USERNAME=ИмяВашегоБота
   ```
3. Перезапустите контейнер бэкенда: `docker compose up -d backend`.

### 2. Функционал Telegram-бота:
* **🔐 Коды подтверждения и 2FA (`/code` или `/verify`)**:
  * При запросе кода на сайте для входа или подтверждения действий бот моментально присылает 6-значный код (`👉 123456 👈`).
  * Пользователь также может нажать кнопку «🔐 Код подтверждения» в боте для получения активного кода.
* **🔗 Привязка профиля (`/link <КОД>` и диплинк `/start <КОД>`)**:
  * В личном кабинете на сайте в блоке «Уведомления в Telegram» нажимается ссылка → бот автоматически привязывает аккаунт.
* **👤 Мой профиль (`/status`)**:
  * Отображает ФИО, email, активные роли, организацию, текущий спортивный разряд и срок его действия.
* **📋 Календарь соревнований (`/competitions`)**:
  * Показывает открытые и ближайшие турниры региона по всем дисциплинам.
* **📰 Новости федерации (`/news`)**:
  * Показывает свежие новости и официальные анонсы федерации.
* **🔔 Автоматические мгновенные уведомления**:
  * Смена статуса заявки на турнир (одобрена / отклонена с причиной).
  * Приказ о присвоении разряда или подтверждении судейской категории.
  * Напоминание об истекающих разрядах (за 30 дней) и дедлайнах соревнований.
  * Массовые оповещения федерации.

## 📧 Оповещения на почту (Email) с кодами и новостями

Файл реализации: `backend/app/services/email_service.py`.

### 1. Настройка почты (SMTP):
В файле `.env` поддерживаются любые почтовые сервисы (Mail.ru, Yandex, Gmail, корпоративный SMTP):
```env
EMAIL_ENABLED=true
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465
SMTP_USER=noreply@example.ru
SMTP_PASSWORD=ваш_пароль_приложения
SMTP_FROM_EMAIL=noreply@example.ru
SMTP_FROM_NAME=ФСП Оренбургской области
SMTP_USE_SSL=true
```

> **Режим разработки (Dev/Demo Mode)**:  
> Если `EMAIL_ENABLED=false` или SMTP не настроен, система **не падает**, а красиво выводит все отправляемые письма, 6-значные коды и новости прямо в консоль бэкенда (`docker compose logs -f backend`). Это гарантирует 100% работоспособность демонстрации в любых условиях без реального почтового сервера.

### 2. Реализованные почтовые сценарии:
1. **Коды верификации**:
   * Эндпоинт `POST /api/v1/auth/request-verification-code`: генерирует 6-значный одноразовый код (срок действия 10 минут) и отправляет его на Email и в Telegram.
   * Эндпоинт `POST /api/v1/auth/login-with-code`: позволяет войти на платформу без ввода пароля только по проверочному коду.
   * На странице логина веб-интерфейса добавлена кнопка **«Вход по проверочному коду (Email / Telegram)»**.
2. **Оповещения о событиях**:
   * При одобрении заявки на соревнование или присвоении разряда на почту пользователя приходит официальное уведомление.
3. **Рассылка общих новостей федерации**:
   * Эндпоинты `GET /api/v1/news` и `POST /api/v1/news` (создание новости).
   * Администратор в личном кабинете или через API публикует новость: она сохраняется в БД, попадает в ленту сайта, отправляется в Telegram-бот и рассылается красивым HTML-письмом всем пользователям (или выбранной роли: спортсмены, тренеры, судьи).

## 🛠 Полезные команды управления

```bash
docker compose ps                        # Статус контейнеров и healthcheck
docker compose logs -f --tail=100        # Логи всех сервисов
docker compose logs -f backend           # Логи бэкенда (включая письма и Telegram)
docker compose restart backend           # Перезапуск бэкенда
docker compose down                      # Остановка с сохранением данных в томах
docker compose down -v                   # Остановка с ПОЛНОЙ ОЧИСТКОЙ данных БД
docker compose up -d --build backend     # Пересборка только бэкенда
```
