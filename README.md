# ФСП Оренбуржье — MVP

React SPA + Express API для региональной федерации спортивного программирования. Основной сценарий: соревнование → индивидуальная заявка → одобрение → результаты → DOCX-протокол → история спортсмена. Все поставляемые персональные данные фиктивные.

## Запуск

Нужен Docker с Compose и запущенный Docker Engine / Docker Desktop.

```sh
docker compose up --build -d
docker compose exec backend npm run db:seed
```

Открыть http://localhost:8080. Первая сборка загружает зависимости и образы. Backend автоматически применяет миграции; frontend ждёт готовности API. Seed идемпотентный: повторный вызов не перезаписывает существующие данные и результаты. Это команда для демонстрационной среды, не для рабочей базы.

Опционально скопировать `.env.example` в `.env`. При смене порта/домена измените и `WEB_PORT`, и `APP_ORIGIN` (точный origin браузера, без завершающего `/`). Для HTTPS задайте `COOKIE_SECURE=true`. Пароль БД в URL должен быть URL-safe. В demo доступны кнопки быстрого входа; перед использованием реальных данных уберите их и демо-пользователей.

```sh
docker compose logs -f backend
docker compose down
```

Обычный `down` сохраняет БД и загруженные файлы в volumes. `docker compose down -v` удаляет их безвозвратно. Сервис db и API доступны только внутри Compose, наружу опубликован frontend.

### Разработка без контейнеров приложений

Нужны Node.js 22.12+ и PostgreSQL 16. У db по умолчанию нет порта на хосте: для локальной разработки используйте собственный PostgreSQL или временный Compose override с привязкой `127.0.0.1:5432:5432`.

```sh
cd backend
cp .env.example .env
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

Во втором терминале:

```sh
cd frontend
npm ci
npm run dev
```

Для Vite установите backend `APP_ORIGIN=http://localhost:5173`. Vite проксирует `/api` в localhost:3001. Проверка сборки: `npm run build` отдельно в backend и frontend. Автоматические тесты намеренно не добавлены.

### Сценарий показа

1. Войти как федерация. Создать соревнование с открытой возрастной группой и будущим дедлайном, выбрать алгоритмическую дисциплину. Сохранить черновик, загрузить положение, назначить судью и открыть регистрацию.
2. В другом профиле браузера войти спортсменом `multi` (у `athlete` уже есть заявка на готовое демо-соревнование). Открыть созданное соревнование, подать заявку.
3. Федерацией открыть вкладку «Заявки», одобрить участника. Закрыть приём, перейти к результатам, заполнить место и баллы, сохранить, опубликовать протокол.
4. Спортсменом открыть «Мои результаты» и скачать DOCX. У судьи проверить назначение, у спортсмена — уведомление.
5. Федерацией изменить баллы, сохранить исправления. Проверить новую версию протокола и запись `RESULTS` с данными до/после в журнале.
6. Тренером найти `multi` по ФИО, запросить привязку по дисциплине. Спортсменом подтвердить; тренером подать заявку на другое открытое соревнование.

Seed также создаёт открытое, закрытое, юниорское, завершённое соревнования и черновик. Даты рассчитываются от первого запуска seed. Для полного показа лучше создать отдельное соревнование.

## Архитектура и модель

`backend/src` — Express-маршруты и общие функции, `backend/prisma` — схема, SQL-миграция и seed. `frontend/src` — страницы SPA, API-клиент и shadcn/ui. Никаких внешних сервисов для запуска не требуется.

- User содержит роли и профиль; Organization и Directory — справочники. Связи справочников контролируются сервером. Дисциплины пользователя хранятся массивом ID, остальные ключевые связи — внешними ключами.
- Session хранит хеш случайного cookie-токена, активную роль и срок 7 дней. Пароли хешируются bcrypt. Role — ADMIN / ATHLETE / COACH / JUDGE.
- Consent хранит версию текста, дату принятия и данные представителя. Без согласия регистрация невозможна; дату рождения после регистрации меняет федерация, несовершеннолетнему требуется сохранённое согласие представителя.
- CoachLink — тренер + спортсмен + дисциплина; состояния PENDING / ACTIVE / REJECTED / ENDED. Повторный запрос после отклонения или завершения обновляет запись, событие остаётся в журнале.
- Competition ссылается на дисциплину, тип и возрастную группу. Application уникальна по соревнованию и спортсмену. Отозванную/отклонённую заявку в MVP повторно подать нельзя.
- Assignment уникален по соревнованию и судье; Result уникален по заявке. Исход FINISHED требует положительного целого места и неотрицательных баллов, DNS/DSQ не имеют места и баллов.
- StoredFile хранит метаданные, сами файлы лежат в volume uploads. Лимит 10 МБ, расширения PDF/DOCX, скачивание требует авторизации; файлы выдаются вложением.
- Notification содержит целевую роль и ключ дедупликации. OutgoingDelivery — заготовка очереди внешних доставок, отправитель не запускается.
- AuditLog — актор, активная роль, действие, объект, время и детали изменения. Изменения бизнес-состояния, журнал и связанные уведомления записываются транзакционно. Операции соревнований блокируют строку соревнования, чтобы приём заявок не пересекался с закрытием/публикацией.

Спортсмен видит свои заявки и результаты, тренер — подтверждённых подопечных по дисциплине, судья — назначения, федерация — все записи. Поиск спортсмена тренером выдаёт только имя, организацию и дисциплины. Протокол с ФИО одобренных участников доступен авторизованным пользователям после публикации. Это граница приватности MVP.

Возраст определяется на дату начала соревнования, в реестре — на текущую дату. История выступлений состоит только из опубликованных результатов. Карточка и положение редактируются до открытия регистрации; состав участников — до публикации. Опубликованные результаты можно исправить, изменив версию. Протокол формируется из текущих данных: изменения профиля отразятся при следующем скачивании; архивные неизменяемые снимки документов в MVP не реализованы.

## API

Все пути начинаются с `/api`, авторизация — cookie `fsp_session`. POST/PATCH/PUT запросы принимают JSON, кроме загрузки файла. Списки возвращают `{items,total,page,limit}`, по умолчанию 20, максимум 100; `/directories` возвращает небольшой полный справочник. Ошибки: `{message,fields?}`; 400 — данные/состояние, 401 — вход, 403 — права, 404 — отсутствует, 409 — конфликт.

| Метод и путь | Назначение |
| --- | --- |
| GET /health | Готовность API и БД |
| POST /auth/register, /auth/login, /auth/logout | Регистрация и сессия |
| GET /auth/me; POST /auth/role | Профиль сессии; `{role}` |
| GET /dashboard | Сводка активного кабинета |
| GET /users?q=&role=&disciplineId=&organizationId=&municipalityId=&rankId=&ageGroupId= | Реестр для федерации / ограниченный поиск тренера |
| GET, PATCH /users/:id | Просмотр / редактирование профиля |
| PUT /users/:id/roles | `{roles:["ATHLETE","COACH"]}`; федерация |
| GET /users/:id/results | Опубликованная история с проверкой доступа |
| GET, POST /organizations; PATCH /organizations/:id | Организации |
| GET, POST /directories; PATCH /directories/:id | Справочники |
| GET, POST /coach-links; PATCH /coach-links/:id | Привязка по дисциплине и смена статуса |
| GET /competitions?q=&disciplineId=&ageGroupId=&status=&eligible= | Календарь; eligible=true для спортсмена |
| POST /competitions; GET, PATCH /competitions/:id | Карточка / создание черновика |

| POST /competitions/:id/applications | `{athleteId}` |
| PATCH /competitions/:id/applications/:applicationId | `{status,reason?}` |
| POST /competitions/:id/assignments | `{judgeId,positionId}`; повторное назначение обновляет должность |
| PUT /competitions/:id/results | `{results:[{applicationId,outcome,place,points}]}` |
| POST /competitions/:id/publish | Публикация всех одобренных результатов |
| GET /competitions/:id/protocol | DOCX текущей версии |
| POST /competitions/:id/files | multipart/form-data, поле `file` |

Создание соревнования: `title,description,disciplineId,typeId,ageGroupId,startsAt,endsAt,deadline,location,format,level,calendarPlan,calendarNumber`; даты — ISO 8601. `format`: OFFLINE/ONLINE/HYBRID, `level`: REGIONAL/INTERREGIONAL/NATIONAL. Регистрация: `email,password,fullName,birthDate,consent:true`, для ребёнка — `guardianName,guardianContact,guardianConsent:true`.

## Что отложено

Это узкий MVP, а не выполнение всех обязательных пунктов кейса. **Внешнего канала уведомлений пока нет:** есть внутренняя доставка и подготовка Telegram. Заявки на разряды/категории, официальные правила ЕВСК, рейтинг, сборная, документы сборной, историческая численность и XLSX-отчёт, остальные отчёты, командные соревнования и дополнительные модули Д1–Д12 не реализованы. Протокол — собственная демонстрационная форма.

Следующий порядок: разряды/категории → рейтинг/сборная → исторические периоды занятий и численность → остальные документы. Для реальной эксплуатации дополнительно понадобятся официальные формы, согласия, размещение по требованиям заказчика и резервное копирование.
